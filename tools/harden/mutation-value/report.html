How the findings changed test review

Checkout pricing

  • Assert the exact discounted total, not merely that a discount happened.
  • Exercise zero, 99, and exactly 100; test membership asymmetrically.
  • Check that membership and coupons stack correctly.

Access control

  • Test exact expiry and the instant just before it.
  • Split role from ownership with asymmetric cases.
  • Check denial against a user who otherwise qualifies for access.

Two checkout survivors only change exception wording. The specification does not promise that wording. They remain in the raw score: 26 / 28 = 92.9%. They are observable changes, not equivalent mutants.

Where this belongs in our quality workflow

Adopted workflow: use a focused mutation pass on changed decision logic after ordinary tests pass. Treat survivors as concrete review questions; add regression tests for meaningful contract gaps and inspect nearby boundary and policy cases. Keep the ordinary test loop fast.

A universal score gate is not supported by these results. A careful requirements and boundary review could produce the same tests without the tool. The user adopted this policy on 2026-10-31; dev ship guidance now selects changed decision-heavy logic and triages survivors against the contract.

What we would measure in a production pilot

Reviewer minutes per actionable finding, duplicate and out-of-contract findings, new regression tests, runtime, and detection of independently selected historical bugs. Compare with equally timed requirements review using separate reviewers where possible. Avoided-defect value must exceed compute, triage, and maintenance costs.

Evidence and limits

Two synthetic programs, 24 executable statements, 39 generated mutation variants, 16 seeded faults. The baselines deliberately include plausible weak assertions and missing boundaries. The same author created all arms and faults, and some faults overlap mutation operators. These results cannot estimate escaped production bugs or long-term developer behavior.

All six main arms ran twice from fresh workspaces and caches. No timeout, suspicious, or untested outcomes were reported. Human effort was not timed. The tiny pure functions omit integration, I/O, and realistic scale.

Tooling and reproducibility

Python 3.14.7 on macOS ARM; mutmut 2.4.4, pytest 8.3.3, coverage 7.6.1. The historical tool version is pinned for this experiment. Full dependency lock, runner, specs, tests, faults, XML, coverage JSON, survivor diffs, and logs live at tools/harden/mutation-value/.

The downloadable JSON preserves both main runs and the score-only ablation. Full reproduction commands and interpretation are in that directory's README.

Broader research context

Google's 2021 long-term study analyzed 15 million mutants and provides observational evidence of test improvements and relationships to real historical faults. Its scaling study uses changed-code review and filtering to contain developer and compute cost. Those findings give context; they do not validate this demonstration's effect size.
